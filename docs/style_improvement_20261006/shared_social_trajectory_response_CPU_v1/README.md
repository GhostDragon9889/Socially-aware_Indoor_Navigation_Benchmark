# 实际终态策略对路线命令的响应

**CPU权重加载与完整前向已实际退出0；动作是否正确仍需物理闭环验证。**

## 方法与来源

NavIsaacLab [IV-B](https://arxiv.org/html/2606.26265v1#S4.SS2)把路线作为目标条件策略的输入。
本批使用原严格Pop-Art actor reader，完整接纳S1／S2预登记2000更新终态及各自原RMS；不选择中途权重。
[实现](../../../scripts/audit_shared_social_trajectory_response.py)只更换原始任务的前20个局部XY目标值，
同一行的身体357维与地图12288维逐值保持；PyTorch2.11 [repeat](https://docs.pytorch.org/docs/2.11/generated/torch.Tensor.repeat.html)
复制存储，原输入没有被修改。

两个模型使用相同的真实S2观测人口：

- 完整validation22的11982个PRE动作观测，包括全部跌倒和失败后帧。
- S2最后一次采集的32×256＝8192条训练观测。它们在最后一次PPO更新之前采集，本批使用更新后的终态actor重新推理，不能称为重放当时的动作。
- 每行六种条件：原观测、原地，以及自体前／后／左／右1m/s直线目标；采样时刻均为+.5、+1、…、+5秒。

共242088个策略输入行实际前向。两模型身体／地图输入相同，RMS没有更新，CPU RNG保持，CUDA／SDK没有启动。
权重、固定2848清单和原物理／风格指标保持。共81项实际输入、10项直接实现来源在执行前后核对。

## 实际结果

下表是每行57个有效归一化动作坐标相对原命令的RMS差，再按完整人口求平均；数值没有物理位移单位。

| 人口／模型 | 原地 | 前进1m/s | 后退1m/s | 左移1m/s | 右移1m/s |
| --- | --- | --- | --- | --- | --- |
| validation11982／S1 | .012469 | .019135 | .022755 | .023850 | .028883 |
| validation11982／S2 | .014131 | .020091 | .024879 | .024393 | .030828 |
| training8192／S1 | .018831 | .019459 | .032607 | .030119 | .030654 |
| training8192／S2 | .016357 | .017160 | .028407 | .025941 | .026998 |

本批策略均值与限幅后动作的差值相同：所有六条件、两模型、两人口的有效坐标均没有严格超出[-1,1]。
原路线前缀超出RMS的clip5边界的坐标，validation中S1／S2为306／302个，占各239640个坐标的约.128%／.126%；
训练原观测及五个替换条件均为0。没有触及clip边界不能证明条件处于训练联合分布内。

按原固定float32 log_std=-2.9计算，S1／S2的validation前进条件等方差、未限幅57维Gaussian KL平均为3.835153／4.281350；
这是策略分布响应诊断，不能解释为限幅后动作分布KL、正确转向或路线成功率。
本批不支持“路线前缀完全未进入策略／所有响应被动作限幅消除”的解释，尚未定位训练失败因果。

S2原条件CPU输出与原GPU捕获动作的最大绝对差为5.429983e-5（归一化动作单位），完整逐行差保留。
没有声称逐位相同或放宽任何原准入门槛。S1档案中的相应数组是跨模型对原S2动作的差，不能作为同模型CPU/GPU一致性结果。
两个原模型的物理跟踪仍0/22；本批没有重新进行SDK模拟或产生风格／路线质量改善证据。
