## One true transition

1. `prepare_control()` returns raw policy input and the original-episode pre-control state_action history. The collector owns clones of self/task/history, ages and current/history episode IDs. Every history row must carry its current actor episode ID.
2. `trainer.act(...)` supplies raw Gaussian actions and the separate exact clamp-to[-1,1]/57-coordinate applied action. PPO retains the raw sample and likelihood. `trainer.amp_reward(pre_history, applied_action)` always consumes h[t] and a[t]. Post-control history is not substituted for the action-conditioned discriminator reward.
3. `world.step(applied_action)` advances exactly four actual120Hz physics substeps and returns a unique pending transition. Before any reset, the collector obtains finite next values on **all N actual post-control observations**, including genuine terminal and healthy collateral actors. A true terminal value is retained rather than forcibly zeroed; the unchanged trainer GAE masks its bootstrap with `~terminated` and stops its carry at `terminated|truncated`.
4. Reward helpers are loaded directly from the unchanged5491B `CrowdSim/humanoid/training/rewards.py` SHA`fc595dd9c1b2012aa76f37dcecd4ec5d7dad50fbd923840736a77c24622a6430`, bypassing the NN-bearing package initializer. The literal trajectory coefficient2, signed-power coefficient−0.0005, direction denominator1.8 and explicitly configured direction/AMP/task weights are reused. Energy uses `pending.signed_power_w`, the World's **four synchronized substep sample mean**, never a new end-only effort proxy. The quantity is generalized projected joint effort times matching joint velocity, in W; it is not proven isolated motor torque.
5. Physical forward velocity uses the **exact unchanged `AMPWorld.planar` method AST** from24834B SHA`1b63a4c8ac7d4bf2f9ed523edc97b41dca89888cdd6c7dcb2234826d240d7f83`. `atan2` is evaluated on the actual Pelvis XYZW quaternion. At a singular projected heading the software result is retained with an explicit defined mask; it is not a measured defined heading. It is kept separately from the World's selected previous-defined task-coordinate continuation. Actual quaternions are never replaced or renormalized here.
6. `world.complete_transition(next_values, archive_callback)` invokes the collector callback before whole-group reset. The callback checks the pending object's identity, absolute control/+4 physics counters, episodes, pre-history and unchanged terminal inputs. It constructs and appends complete owned training and diagnostic step dictionaries **before** any optional external archive callback. The external callback receives another independent copy. Its successful return is an in-process declaration, not independently verified durable storage.
7. Only after that callback returns does the World reset groups. A later control obtains the correctly rebound history and new episodes. At completion the collector stacks all T steps, calls the unchanged rollout validator from4545B SHA`26c7379ba60842c67f062fa5c1a3459ddfb6e0843e1b4952e1d078aa6f78cdad` and checks that no control or pending transition was lost.

`collect(T)` returns three separate dictionaries:

- `rollout`: only fields already supported by the trainer: required PPO/state_action tensors, episode/history IDs and its optional reward/power/forward-velocity diagnostics. This dictionary alone is passed to `trainer.update`.
- `diagnostics`: pre/post ages and history, all terminal policy inputs, mean actions, reference XY, physical root quaternion, software reward heading, task continuation masks, separate physical-fall/normal-contact/source-end/cap/collateral/reset masks, nonfoot resultant normal force, COMMON body/DOF snapshots, independent native-root link snapshots and actual pre/post counters. A collateral truncation is never relabeled as a cap or physical fall.
- `metadata`: exact configuration, owned frozen four-RMS buffers, training counters and control range, explicit reward/power/frame semantics, archival declaration and the absence of SDK checkpoint recovery. Returned Tensor metadata is an in-process object; this source does not choose a durable serialization format.

After a successful return the caller supplies its already prepared real expert batch and calls `trainer.update(result["rollout"], expert_history, expert_applied_actions)`. This source does not choose expert actions, schedule updates, provide an executable launcher or attest to a full SDK resume. Those runner responsibilities are still pending.

## Frozen behavior policy and failure handling

At each rollout start all four original RMS buffers, counts and clip values are cloned. Fresh self/task/value counts must equal the trainer's physical transition counter. Every key observation/action/AMP/value/archive/control boundary checks exact RMS buffers, configuration, action mask and both training counters. The existing sealed act/value/amp_reward methods are `no_grad` and have no training/moment-update path.

The complete model parameter/buffer data and module identities/modes are cloned once per rollout. Exact equality is checked at the end and immediately before/after any external archive callback. It is **not** scanned after every ordinary act/AMP/value call, and private Tensor version counters are not used as a substitute for data equality. This is a first strict correctness implementation: device synchronizations, clone memory and comparison cost are unmeasured. No performance improvement is claimed.

Any failure during collection, including KeyboardInterrupt or SystemExit, propagates and permanently faults the collector and World. `failed_steps` preserves already owned local step lists, including a step appended before an external archive failure. They are diagnostic partial data, never a returned successful rollout. No automatic retry, rollback, missing-frame recovery, physical checkpoint restore or replay of failed SDK side effects is attempted. Validation rejected before collection begins has no physical side effect.
