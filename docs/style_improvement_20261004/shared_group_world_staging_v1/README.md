# Shared four-Articulation world driver — source preparation

This directory contains a bounded physical driver, **not a complete training runner**. Four fake-boundary CPU tests have now executed intact driver methods, with CUDA hidden and no NN or SDK execution. Real physics, AMASS data, model weights, captures and training remain untested for this driver. Production185 and all earlier sources/proofs remain unchanged.

## Construction and ownership

`SharedGroupWorld.create_after_app(...)` receives one live, caller-owned App, an explicit120Hz PhysX configuration, reviewed single-SMPL USD/PD template and base scene configuration. A future SDK entry must launch the App through the existing import-before-Torch bootstrap **before importing this Torch-based driver**. It refuses an existing `SimulationContext`; it never initializes or replaces the old single-robot `AMPWorld`. The sealed factory constructs four independent assets `robot_0..3`/`Robot_0..3` in each of G=N/4 envs, with `filter_collisions=True`, shared global collision assets and per-slot separation declared by the caller. N=256 gives64 environments and canonical groups `[2g,2g+1,128+2g,129+2g]`.

The caller owns App/context shutdown and cleanup on construction failure. `sim.reset()` is initialization, followed by a recorded baseline; it is not included in control transitions. The driver does not create an App, change the solver recipe, render, seed an RNG, write logs or launch a policy. Real within-group contact and cross-group filtering remain to be demonstrated by the separately prepared exclusive SDK smoke; configuration source alone does not prove them.

The original fresh `MixedTrajectoryCurriculum` is prepared by the caller. Its class, module origin, N and device are checked, and already-bound curriculum objects are rejected because physical checkpoint recovery is pending. First-half AMASS/second-half procedural identity is preserved. Original reset clip/frame draw order and private/shared generators are used; no reseeding or reclassification occurs. The normal-force bundle factory supplies existing exact-path views, layouts and sensor body-name order for every actor; it must not advance physics. Creating scalable native views and validating their physics ownership are future SDK responsibilities.

## One control and terminal consumption

1. `prepare_control()` plans on global15-control ticks or a reset-invalid/overdue plan, then returns finite rawself357/rawtask12308 and newest-first history10×195 on all N actor rows. It retains the pre-control state_action history and episode IDs. The sealed task/raster interfaces keep20 unscaled world-meter trajectory coordinates at +0.5..5s, HWC64²×3 and current peer state only; normalization and raw symmetry belong to the separately prepared social trainer.
2. The caller's `trainer.act(pre.self_obs, pre.task_obs)` produces raw and applied actions. `step(applied_actions)` requires already clamped canonical69 with the declared57-coordinate hand/toe mask. It derives COMMON PD position targets using the two exact original decoder function ASTs, actual native joint limits and explicit names. Raw samples are not mislabeled as PD targets.
3. Four120Hz substeps each perform targets → `scene.write_data_to_sim()` → `sim.step(render=False)` → `scene.update(1/120)`. The actual counter must increase exactly once per substep. After each, every asset's `root_view.get_dof_projected_joint_forces()` and freshly accessed `data.joint_vel` are cloned, mapped by native semantic DOF names and gathered into canonical rows. Their signed product sum is averaged over four samples in watts. It is measured **generalized projected joint effort**, including the solver channel; it is not isolated motor torque, the ImplicitActuator PD estimate, absolute power or joules.
4. At the fourth substep end, owned COMMON link snapshots and independent native-root link fields are read. Age/plan age/control/history advance once. Actual falls use the existing ground-relative Pelvis height `<0.45m` or root-up-Z `<0.1`. Current all-partner body net **normal** force is sampled once with actual dt1/120; the sealed predicate excludes ankles/toes, sums body vectors, takes norm `>50N`, and requires episode progress `>1`. No peer-pair max, geometric raster/proxy, four-substep max, impulse or friction equivalence is substituted. Physical-fall/contact/source-end/cap causes remain separate.
5. The Torch adaptation of sealed group-reset semantics preserves each true terminated flag. Any original terminated/truncated actor triggers its whole group; healthy collateral actors become **truncated**, with a distinct collateral mask. Every terminal, truncated, fallen, idle and healthy actor is present in the returned post-control observations, original episodes, pose, history, power and flags. No physical reset happens in `step`.
6. The caller obtains finite next values from the **same original-episode post observations**, then invokes `complete_transition(next_values[N], archive_callback)`. The pending control/episode identity is checked. The callback receives the complete terminal transition and owned next values before reset. Its successful return is an in-process fact, **not independently verified archival proof**. GAE must preserve the trainer's existing `bootstrap=~terminated` and `carry=~(terminated|truncated)` semantics; true terminal values must not bootstrap.
7. Only after the callback returns does the driver reset complete groups. Four partial index writers, actuator/sensor buffers and official `sim.forward()` FK are used, with no extra physics step. History/reference/plan-validity/episode/heading context are synchronized for all reset actors; the absolute control clock stays monotonic. A fresh plan is built at the next policy preparation, so reset does not consume an extra procedural draw.

Input-validation failure before side effects permits correcting the input. Preparation/control/archive/reset failures, including KeyboardInterrupt and SystemExit after possible side effects, propagate and fault the driver; there is no automatic retry, transaction, rollback or physical recovery claim. Next values are externally denormalized trainer values. No critic, reward combination, expert discriminator update, PPO update or external archive implementation is hidden here.

## Explicit geometry and singular fallen heading

`ground_height_at(queryXY)` returns absolute static ground Z in float32 on the input device without mutating its query. `terrain_sampler(gridWorldXY)` follows the sealed batch grid callback: one float64 N×64×64×2 query, finite on-device absolute static Z and no mutation. These callbacks must refer to the actual static scene, with adequate floor/trajectory coverage. This stage cannot infer height from an occupied social proxy.

`grid_geometry_contract` is a mandatory exact three-field dictionary: `grid_center` and `grid_heading` each choose `root` or `head`; `height_reference` chooses `root_z` or `static_center_ground_z`. It is copied into an owned readonly mapping, checked before SDK side effects, and returned separately by `describe()`. The collector must match it to the training configuration. This validates declarations; actual callback geometry still needs runtime verification.

`grid_geometry(owned_snapshot, used_task_heading, task_heading_defined)` explicitly returns centersXY, grid headings and height-reference world Z in float32. Root versus Head center/heading and root/ground reference are caller choices; no private NavIsaacLab convention or the old32² head grid is inferred. The grid frame may be independent of task/root velocity frames. Future changing terrain or anticipated peer poses must not enter this callback.

The sealed projected-root-X helper still rejects `hypot(directionX,directionY)<=1e-12`. The driver uses its exact FP32 direction formulas and tests the same boundary. Only a genuinely fallen actor with an earlier **actual defined** heading in the same episode may continue task coordinates using that heading. Reset must establish a new actually defined heading; it never guesses0 or carries the old episode's frame. Healthy/collateral actors retain their actual defined heading. Actual quaternions are untouched, and every returned transition stores `actual_root_quat_xyzw`, `used_task_heading`, `task_heading_defined` and `singular_heading_fallback`. Planar history additionally keeps heading-defined masks.

This is an explicitly selected **task-coordinate continuation**. Raster rectangles for such fallen actors also use that declared proxy heading; it is not their measured current heading or collision truth. The original self357 function independently retains its `rotations.calc_heading_quat_inv`/projected-X `atan2` behavior, without driver continuation. A singular pose can therefore have different self and task coordinate conventions; this stage does not claim those frames coincide. Physical and rotation metrics retain the actual quaternion. A singular healthy pose, missing per-episode context, invalid quaternion or nonfinite state fails explicitly. Real fallen SDK behavior and value consumption still require later validation.

## History, counters and resource boundaries

Reset AMP history retains the original method: ten newest-first **corpus reference** features, with row0 replaced by the actual reset physical snapshot. The remaining nine are not claimed to be actual prior physics in the new episode. They are assigned the new episode ID exactly as in the original source. The91-row planar buffer is initially repeated current state, but only its final sample is available; it is not91 genuine prior controls. New physics advances both buffers once, and group reset masks all prior planar availability/heading-defined history.

Source-end observation queries use the original declared tail policy rather than another physical step: AMASS `_phase` permits age exactly equal to remaining steps; `_sample_xy` clamps source frame indices to the last real frame and either holds the endpoint or adds the configured command-only linear-velocity tail. `future_targets` may therefore return finite commands at the terminal source end before reset; it does not claim future AMASS poses or continue the physical episode. Procedural future queries retain original51-knot endpoint clamping. The driver does not replace `linear_velocity` with `hold`, select a new clip, consume a new reset draw or replan after terminal physics before next values.

`describe()` removes original fall-named statistics from its headline curriculum view and groups them by source path under `legacy_aggregate_terminal_counts`: the original opaque curriculum `state_dict` still has its exact old keys, which now count all supplied terminal causes, including contact. Separate driver counters retain physical falls, normal-contact terminations, original terminal controls, source ends, caps, collateral truncations and triggered resets. Initialization reset rows are counted separately. Actor-control denominators always include all N rows.

Snapshots are owned clones; the frozen adapter performs named SIMULATOR↔COMMON conversion before/after the frozen bridge changes actor rows. Link velocities are used, not COM aliases. Pose/velocity/world-Z, body/DOF dimensions and quaternion order are not changed by row mapping. `grid_geometry` and the archive callback receive owned snapshots rather than live world buffer aliases. Completion metadata keeps only the most recent callback outcome; it is not an unbounded evidence log.

Local reset-cache source check: the adapter's index writers retain the SDK default `skip_forward=False`. Root-pose writer calls `_reset_pose`; root-link-velocity writer calls `_reset_velocity(from_com=False)`; fused joint writer calls both reset helpers. Installed data invalidates body pose/velocity timestamps and sets `_fk_timestamp=-1`. A fresh body-link getter calls `_ensure_fk_fresh()` and `update_articulations_kinematic()` independently of a physics step. `sim.forward()` additionally synchronizes FK/fabric when fabric is present; it is not the sole refresh guarantee when rendering/fabric is absent. `scene.reset()` resets actuator/external-wrench/sensor buffers, without writing default physical states. No `scene.update(0)` or positive fictitious time increment is used. These are API/source facts, not an executed reset-physics result.
