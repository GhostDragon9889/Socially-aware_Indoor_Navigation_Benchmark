# Prepared PACER reward Warehouse4/15 protocol

Preparation only: no future checkpoint, capture or quality is admitted.
Root owns the single GPU and actual child-process closure. This directory
provides registered commands and SDK-free admission functions; it starts no
simulation or subprocess.

## Preserved physical protocol

Commands are materialized from the original `launch_native_v2.py` command-list
AST. Only the AMP checkpoint, explicit profile and fresh output aliases change.
The existing Warehouse **V5** four-/fifteen-actor scene files, 200 seconds,
6,000 controls, seed 7, inference-only mode and arm alpha 0 remain identical.
No native V5 resource, historical source or production file is edited.

Production bytes are the **185-file V12** roster `9ddbfe99…` and its exact
archive `9a3cd41a…`. The opt-in public profile is `6d76dbfa…`. The future
controller is the registered isolated PACER reward `step_2000.pt`; its bytes
and SHA remain null until the actual terminal reader admits the sealed file.
The full terminal guard is reused from the frozen new evaluator and reader,
including five reward fields and coupled state-prior provenance.

## Physical progression

1. Admit the actual terminal controller and a complete **4 × 6,000** fixture
   raw report, with zero falls, static contacts and peer contacts.
2. Require the actual raw CPU process to have closed successfully, with its
   command and report/sidecar artifact bytes bound to this trial.
3. Run native4 serially. Retain its complete or failed result.
4. Run native15 only after the independent new native4 raw reader observes a
   complete 200 seconds with zero falls, static contacts and peer contacts,
   bound to its actual closed root process and the same controller/source.

**Style scores are not launch gates.** Completed failed results remain retained.
These are local physical stress tests, with no assertion of author eight-scene
equivalence or automatic default promotion.

## Admission interface

`validate_native_admission.py` exposes:

- `prepare_sources()` / `read_registration()`: current regular source/archive
  and registered resource bytes only; no future model or output read.
- `native_command(actors)`: the fixed command for actors 4 or 15.
- `validate_terminal(document, checkpoint)`: existing complete terminal guard.
- `validate_fixture(report, sidecar, receipt, checkpoint)`: actual fixture raw
  measurement, frozen producer/catalog and artifact-bound CPU closure.
- `validate_closed_receipt(receipt, actors, checkpoint)`: registered native
  command, actual observed exit 0, source bytes before/after and controller.
- `validate_closed_native(document, actors, checkpoint)`: the independent raw
  audit, complete physical counts and actual source/owner/controller provenance.

The root native receipt schema is `pacer_reward.actual_native_launch.v1`.
Required fields include `actors`, `status="closed"`, exact integer
`exit_code=0`, `child_exit_observed=true`, `driver_completed=true`,
`prepare_only=false`, the registered `command`, complete `amp_checkpoint`
record, and `selected_source_before/after` equal to the prepared production
source record. The actual receipt paths are fixed in each registered case.

The root raw CPU receipt schema is `pacer_reward.actual_CPU_metric_launch.v1`,
with `metric="navigation_raw"`, CPU-only true, observed closed exit 0 and its
exact registered command. `artifacts.raw_report` and `artifacts.source_sidecar`
must contain actual full path/bytes/SHA records. A preparation receipt never
counts as an actual metric-process closure.

The actual native raw audit schema is
`pacer_reward.native200s_independent_CPU_audit.v1`; no future report is created
by preparation. Its independent reader keeps the existing raw mathematics.
